# Yuki wake-word training

This is a reproducible **training runbook and preflight gate**, not a claim that a
wake-word model has already been trained. Training runs on a managed Linux GPU
runtime such as Kaggle; it does not require the user's Android phone or local PC.

## Design

- Phrase: the single English wake word `Yuki` (target pronunciation: “YOO-kee”). Do not prepend “Hey”.
- Include speaker, accent, distance and room-noise variation. Train hard negatives for near-homophones such as “you key”, “you keep”, “cookie” and “you see”; measure false activations on natural conversation, not only synthetic clips.
- Training framework: upstream [openWakeWord](https://github.com/dscripka/openWakeWord)
  custom-model trainer, pinned to release `v0.6.0` for the initial reproducible
  experiment. Review upstream changes before upgrading.
- Compute: Kaggle Notebook with a GPU accelerator. The model head is small, but
  synthetic audio generation, augmentation and feature extraction dominate
  runtime and storage.
- Positive examples: synthetic multi-speaker English samples generated by the
  upstream Piper sample generator. Only use a TTS checkpoint/voice whose
  license and training rights have been reviewed.
- Negative examples: separately sourced, license-cleared speech/noise/music,
  plus phonetically confusing phrases generated by the upstream trainer.
- Evaluation: separate positive and negative validation data. Tune thresholds
  against long-form audio that represents the actual desktop environment.
- Output: ONNX model, run metadata, dataset manifest and evaluation report.
  TFLite export is optional; desktop runtime integration will use a tested
  format/backend, not assume the training export is production-ready.

openWakeWord recommends thousands of positive samples and large, diverse
negative audio coverage. Its own documented targets (roughly below 5% false
rejects and below 0.5 false accepts/hour) are goals to measure, not guarantees.
The upstream project describes English support and its custom training path in
its [README](https://github.com/dscripka/openWakeWord#training-new-models).

## Licensing gate — do not skip

Every training asset must have a record in `assets.manifest.json` with:
- source URL and exact license URL/identifier;
- SHA-256 of the exact local file;
- role (TTS model, background audio, room impulse response, negative feature
  corpus, validation recording, etc.);
- human-reviewed permission to use for training;
- separate permission to redistribute the asset, if redistribution is planned.

A license label is not proof of permission. Do not assume that public download
means commercial training, model redistribution, or inclusion in a desktop
installer is allowed. Keep raw audio, generated clips, model checkpoints and
private recordings out of Git. Do not upload private recordings to Kaggle or
Hugging Face unless their owner has explicitly approved that transfer.

The example manifest is deliberately invalid. Copy it to the dataset root,
replace every placeholder, review each upstream license, then run:

```bash
python training/wakeword/validate_assets.py /path/to/dataset/assets.manifest.json
```

To require redistribution rights for every asset (a stricter gate for assets
that will be shipped with Yuki):

```bash
python training/wakeword/validate_assets.py /path/to/dataset/assets.manifest.json --require-redistribution
```

## Kaggle workflow

1. Create a **private Kaggle Dataset** containing the approved training assets
   and its completed `assets.manifest.json`. Do not place secrets in the
   dataset or notebook.
2. Create a Kaggle Notebook, attach that dataset, enable a GPU accelerator,
   and verify the GPU is available with `torch.cuda.is_available()`.
3. Clone this Yuki repository and the upstream openWakeWord repository at
   `v0.6.0`. Record the exact resolved Git commit SHA in the run metadata.
4. Set up the upstream training environment using the upstream
   `notebooks/automatic_model_training.ipynb` as the dependency reference.
   It is an older notebook and its pinned TensorFlow/Piper dependencies may
   need compatibility work on the current Kaggle image. Do not silently
   upgrade or downgrade packages; record the exact installed versions.
5. Place the vetted Piper sample-generator checkout and approved TTS checkpoint
   at the paths declared in the YAML. Verify their licenses independently.
6. Copy `yuki.template.yaml` to `yuki.yaml`, adjust paths to the
   attached dataset, and run the asset manifest validator before training.
7. Run the three upstream phases separately so Kaggle output can be checkpointed:

```bash
python openwakeword/train.py --training_config yuki.yaml --generate_clips
python openwakeword/train.py --training_config yuki.yaml --augment_clips
python openwakeword/train.py --training_config yuki.yaml --train_model
```

8. Save `artifacts/yuki/yuki.onnx`, the training YAML, manifest,
   source commit SHAs, dependency lock/export, logs and evaluation outputs to a
   **private** Kaggle Dataset version. Do not publish a model until all
   training-data and model-asset rights have been reviewed.

### Important upstream compatibility note

The upstream v0.6.0 trainer uses legacy dependencies and a YAML loader that
should only be given a trusted, locally reviewed config. Treat the notebook as
a controlled training environment, not as a general-purpose file upload
service. Never run an untrusted training YAML or third-party setup script with
Kaggle credentials attached.

## Dataset layout

```text
dataset/
  assets.manifest.json
  data/
    background/           # licensed background clips
    rir/                  # licensed room impulse responses
    features/
      negative_train.npy  # precomputed 16 kHz openWakeWord embeddings
      negative_validation.npy
  tts/
    approved_voice_model/ # only if its terms permit this use
```

The feature arrays must be generated with the same compatible openWakeWord
feature extractor used by the trainer. Do not mix embeddings from different
front-end versions. Keep training and validation sources disjoint to avoid
leakage. The example YAML expects the two negative feature arrays; they are
not bundled here because a suitable license-cleared corpus has not yet been
selected.

## Acceptance gates before desktop integration

A training run is a research artifact until it passes all of these:

- [ ] Manifest validates and every source license is reviewed.
- [ ] Positive set has varied voices, rates, pronunciations and realistic SNR.
- [ ] Negative set covers speech, music, TV, room noise and near-phrase confusables.
- [ ] Train/validation/test splits are disjoint by source speaker and recording.
- [ ] Report false rejects by speaker/accent and SNR.
- [ ] Measure false activations per hour on long-form, held-out mixed audio.
- [ ] Tune threshold and consecutive-trigger behavior on held-out recordings.
- [ ] Benchmark CPU, RAM, latency and thermal load on target desktop hardware.
- [ ] Verify model file hash, provenance, license and export compatibility.
- [ ] Keep wake activation separate from identity, permissions and tool authorization.

A model will not be promoted just because training loss looks good. If a clean,
representative negative validation corpus is unavailable, stop at a baseline
experiment and do not claim a production false-activation rate.
