# Phase 101 — isolated skill environment planning

## Goal

Introduce a safe foundation for per-skill Python environments while keeping Yuki's core interpreter untouched.

## Implemented

- Validate a bounded lockfile format containing normalized package names, exact numeric versions and SHA-256 hashes.
- Reject duplicate normalized package names, unpinned versions, malformed hashes and oversized lockfiles.
- Render deterministic pip `--require-hashes` requirements content.
- Generate per-skill/per-version virtual-environment paths.
- Generate exact venv creation and offline pip installation argv.
- Require absolute, existing, non-symlink environment-root, Python executable and wheelhouse paths.
- Refuse existing environment and lockfile destinations rather than overwriting them.
- Pin the lockfile content digest in the returned plan.
- Generate installation commands with `--no-index`, `--only-binary=:all:`, `--require-hashes`, and pip `--isolated`.
- Register the feature as experimental with capability evidence.

## Example

```python
plan = plan_skill_environment(
    skill_id="writer",
    skill_version="1.2.0",
    environment_root="/var/lib/yuki/skill-envs",
    python_executable="/usr/bin/python3",
    wheelhouse="/var/lib/yuki/wheelhouse",
    lock_entries=[{
        "name": "PyYAML",
        "version": "6.0.2",
        "sha256": "<64-character trusted artifact digest>",
    }],
)
```

## Security boundaries

- This module is a planner only. It does not create directories, write lockfiles, create virtual environments, launch subprocesses, install packages or access a network.
- The lockfile must be generated by a trusted resolver that captures the complete transitive dependency closure and verified artifact hashes.
- Offline installation must use a pre-populated, trusted wheelhouse; `--no-index` prevents package-index resolution.
- Hashes alone do not establish publisher identity or artifact safety. Wheel provenance, signature verification, malware scanning and artifact attestation are not implemented.
- The generated argv is not an authorization token. A future executor must revalidate paths and plan digest, require explicit user approval, enforce resource limits and audit every action.
- Per-skill venvs are not a security sandbox. Untrusted code still requires OS-level isolation; reuse the existing fail-closed sandbox policy/runtime where applicable.
- No automatic installation, rollback, environment cleanup, CLI or desktop integration is included.
