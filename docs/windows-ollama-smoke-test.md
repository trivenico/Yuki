# Windows: real Ollama inference smoke test

This is an explicit acceptance check for the local provider path. It sends one short prompt to your configured local Ollama model. It does not call cloud providers, select a mock provider, install software, or modify your configuration.

## 1. Start Ollama and verify a model

Open PowerShell:

```powershell
ollama --version
ollama list
```

If the list is empty, pull a model suitable for your hardware, for example:

```powershell
ollama pull llama3.2:3b
```

Model size and performance depend on available RAM/VRAM. Use a model already installed if you have one.

## 2. Configure Yuki for Ollama

In Yuki's configuration, set:

```yaml
provider: ollama
ollama_base_url: http://127.0.0.1:11434
ollama_model: llama3.2:3b
```

Use the exact model name shown by `ollama list`. Alternatively, PowerShell can override the provider/model for the current terminal session:

```powershell
$env:YUKI_PROVIDER = "ollama"
$env:YUKI_OLLAMA_MODEL = "llama3.2:3b"
```

These environment overrides apply only to that PowerShell session. They do not persist after it closes. Do not place API keys in YAML or commit credentials.

## 3. Run the smoke test

From the Yuki repository root, after installing the project dependencies:

```powershell
python scripts/smoke_test_ollama.py
```

Expected success includes `PASS: real Ollama inference returned a non-empty response.` The script returns a non-zero exit code on configuration, connectivity, missing-model, or inference failure. It never silently switches to mock or cloud inference.

## 4. Test the actual CLI separately

After the smoke test passes, start the normal Yuki CLI using the repository's documented startup command and run `/status`, then `/ask Reply with exactly: YUKI_CLI_SMOKE_OK`. Confirm the answer is generated by the configured local model. Restart Yuki and repeat `/status` to verify the selected provider/model persist.

## What this does not prove

A passing script validates local provider connectivity and one real generation call. It does not verify every CLI command, desktop behavior, tool approvals, memory persistence, long-running tasks, or production security. Run the full unit suite and desktop acceptance checks separately.
