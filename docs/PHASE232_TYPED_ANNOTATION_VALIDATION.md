# Phase 232 — Typed annotation submission contracts

## Delivery

The annotation service now validates human submissions against the project's task family before writing a submission. Validation occurs inside the same SQLite write transaction that checks task ownership, optimistic version, project status and AI-assistance policy. A rejected payload creates no submission and does not advance the task version.

Supported contracts:

- Image and text classification: one rubric-valid label, optional confidence in [0, 1], optional rationale.
- Bounding boxes: non-empty list, rubric-valid labels, normalized coordinates and positive dimensions fully inside [0, 1] image space.
- Polygon segmentation: rubric-valid labels and at least three normalized points per polygon.
- Video tracking: stable track identifiers, rubric-valid labels and strictly increasing non-negative integer frame indexes; each frame has a normalized in-bounds box.
- Audio transcription: non-empty timed segments with non-empty text.
- Speaker diarization: timed segments must also identify a speaker.
- Entity extraction: typed text/label/character offsets; when the rubric supplies source_text, offsets must match exact source substrings. Spans are ordered and non-overlapping.
- Response ranking: at least two unique response IDs with unique contiguous integer ranks starting at one.
- LLM evaluation: one or more named finite numeric scores from 0 through 5.
- Custom: retains the bounded JSON-object contract for client-defined schemas.

Unknown fields are rejected for typed task families to catch misspelled fields and ambiguous payloads. Booleans are not accepted as numeric values. NaN and infinity are rejected. The existing global JSON byte limit remains in force.

## Security and correctness boundaries

- The project task type and rubric are read from the owner-scoped database row, never trusted from a submit request.
- Validation executes after owner/task/version checks and before submission insert.
- The annotation audit trail remains metadata-only.
- AI suggestions are not generated by this phase; human confirmation and project AI policy remain unchanged.
- This is schema validation, not visual geometry review, temporal media decoding, ontology validation, or proof that the annotation is semantically correct.
- Coordinates are normalized to [0, 1]; frame indexes are zero-based non-negative integers; audio times are seconds.

## Tests

The new tests cover task-family shape/range constraints, rubric labels, audio timing, entity offsets, ranking uniqueness and score finiteness. Existing workbench tests continue to exercise transactional lifecycle and audit behavior. The GitHub cross-platform quality workflow is the release gate; no local test run is claimed.

## Remaining Phase 232 work

A functional Textual workbench screen, task navigation, input editors, explicit save/claim/submit controls, recoverable stale-version conflicts, review queue and progress reporting remain outstanding. The asset API currently buffers bounded uploads and does not provide a browser-grade media viewer. Do not advertise the workbench as ready for paid client projects until those client-facing and operational controls are complete.
