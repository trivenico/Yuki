# Phase 8 — ReAct, daemon, messaging, skill proposals, providers

This phase adds opt-in primitives; it does not enable unattended privileged actions by default.

## ReAct/tool calling
- Register only application-owned `ToolSpec` handlers with JSON-object schemas.
- Configure a provider implementing `complete_tool_turn(messages, tools)`; `OpenAIToolCallingProvider` supports OpenAI Chat Completions tool-call payloads and compatible servers.
- High/medium/critical tools always require an approval callback; low-risk tools require approval unless explicitly marked `auto_approve=True`.
- Provider adapter work is still required for Anthropic's native Messages tool schema and provider-specific error/retry semantics.

## Daemon and cron
- Store jobs in SQLite using `DurableTaskQueue`; register named async handlers only.
- Schedule cron expressions with `CronScheduler` and call `tick()` once per minute from a supervised process.
- The queue retries failures with bounded exponential delay. Configure OS service supervision (systemd/launchd/Windows Service) separately.
- Job payloads never contain import paths or shell commands. Add idempotency keys for business jobs before deploying duplicate-sensitive work.

## Messaging
- `MessagingGateway` provides user allowlisting and bounded message dispatch; `verify_hmac_sha256` is a generic webhook primitive.
- Each platform needs its own signature verification and event normalization before calling `dispatch`. Telegram/Discord/Slack/WhatsApp production adapters are not claimed as complete by these primitives alone.
- Keep outbound credentials in environment/secret storage; restrict ingress with TLS, rate limits, replay protection, and allowlists.

## Skill synthesis
- `SkillProposalStore` stages declarative `SKILL.md` proposals. Frontmatter is JSON, so it can be parsed without a YAML dependency.
- Review is hash-bound. Only low-risk declarative proposals can be promoted to the active directory. Python generated by a model is never imported or run.
- Promotion does not execute instructions. Wire a separate reviewed declarative-skill interpreter into the app registry before claiming runtime activation.

## Provider hardware
- `create_local_tool_provider` presets cover OpenAI-compatible vLLM, llama.cpp server, LM Studio, and MLX server endpoints.
- Ollama's current text-only adapter remains unchanged. Automatic load balancing, health-aware failover, MLX native bindings, and Anthropic-native tool calling are future integration work.
- Local HTTP is accepted only for loopback; non-loopback endpoints must use HTTPS.

## Onboarding
Run `python -m ui.onboarding_tui`. Config defaults to `~/.yuki/config.json`; secrets are represented by environment-variable names only. Existing YAML runtime config is not automatically migrated by this starter wizard.

## Verification
Run `python -m unittest discover -s tests -v`. Keep daemon, messaging, generated-skill activation, and autonomous actions disabled until platform integration tests and security review are complete.
